Task 4b: funding model

One engine, four ways in

Every page below runs the same calculation engine on the same data. Costs, revenue, eligibility rules, federal share caps, and match are defined once, in engine/funding-engine.js, and every rule is listed with its source in RULES.md. The data follows schema.sql. The pages differ only in what they put first.

Simple view: assumptions and what-if

Every cost and funding input on one page, with what changes when dollars change.

  • All inputs with their source cells
  • Multipliers by funding level and source
  • Value of $100,000 more, and cost of losing each source

A. Budget scenarios

For decision makers: test funding futures and compare them.

  • Presets: SB 125 ends, partners return, pooling
  • Sliders by level and agency
  • Saved scenarios side by side, five-year view

B. Allocation workbench

For staff: set how each source is split and check it rule by rule.

  • Editable shares matrix with rule coloring
  • Findings by rule ID
  • Service waterfall with the match arithmetic

C. Partner cost share

For partners: who pays for what, and on what commitment.

  • Cost and local share by jurisdiction
  • Cost-share formula builder (miles, hours, stops, riders)
  • Regional formula against current contributions

Engine, data, and checks

  • engine/funding-engine.js: all funding logic and the rule registry; no UI code
  • RULES.md: 52 general rules and the rules for each of 63 sources
  • schema.sql: database schema (SQLite, PostgreSQL-compatible)
  • data/seed.json: the data as normalized tables; data/funding_model.sqlite is the same data loaded with keys enforced
  • tests/engine-tests.html: 54 checks, including 200 random funding scenarios with proven-optimal allocations
  • tools/verify.py: re-reads 122 values from the workbooks and re-solves the optimizer independently
  • tools/seed_source.py: where data values and citations are edited; tools/build.py regenerates the data files
